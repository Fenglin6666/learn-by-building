# learn-by-building

> 不是让 AI 写得更快，是让 AI 写得更少。
>
> 目标不是"这次做完了"，是**下一次遇到同类的事，你能自己来——包括自己设计**。

一个给 AI 编码助手用的**学习协议**。它把「AI 设计 + AI 写代码 + 你点头」，改成「AI 给设计和理由 + 你写代码 + 你练迁移」。

---

## 它治什么病

写下这个协议的人的原话：

> 当我有一个点子、把它描述给 AI 来完成，往往效果不好。代码很多，我自己想改根本无从下手。最关键的是，我在整个过程中学到的东西寥寥无几，最多是一些概念。
>
> 本质上我只是把项目外包给了 AI——这更像是一种雇主关系，而不是伙伴关系。

对照一下你是不是也这样：

- [ ] 点子丢给 AI，出来的东西不太对，但也说不上哪里不对
- [ ] 代码能跑，但我不敢动，一动就崩
- [ ] 项目做完了，我能讲出几个名词，但讲不出它为什么这么组织
- [ ] **做完一个项目，下一个类似的项目我还是从零问 AI**

最后一条是关键。前三条是症状，它是判决书。

---

## 核心诊断：做完 ≠ 学到

AI 一次性把**设计、实现、判断**全做完了，你只做三件事：描述需求、点头、运行。这三件事都不产生能力。

把"做一遍"变成"学到"，过程中必须长出三样东西：

| 要长出的东西 | 没有它会怎样 | 靠什么长 |
|---|---|---|
| **结构感**：知道自己在写的东西在系统里什么位置 | 会写函数，拼不成系统 | 模块定位 + 自己画模块图 |
| **判断力**：能看出好坏，不等 AI 说 | 永远在接收结论 | Review 时先自己判断 |
| **可迁移的模式**：同一套结构换个场景能自己搭 | 做完就忘，下次重来 | **同构模块对** |

第三样是最终标准，前两样是它的前提。

---

## 核心机制：同构模块对

**迁移不会自己发生。必须在项目里人为安排一次「同一结构做两遍」的机会。**

设计阶段就定下来：这个项目里哪两个模块是同构的。

- 第一个：AI 带（给设计、给骨架、给步骤）
- 第二个：AI 放手（只提醒一句"这个和上次那个结构一样"，然后闭嘴）

| 同构对 | 共同结构 |
|---|---|
| 读 CSV / 读 JSON | 解析 → 校验 → 转成统一结构 |
| 导入 / 导出 | 方向相反，字段映射一样 |
| 用户列表页 / 订单列表页 | 查询 → 分页 → 渲染 |
| 登录校验 / 权限校验 | 取凭证 → 验 → 放行或拒绝 |

**如果项目里天然没有同构对，就加一个。** 加一个"导出"功能最便宜——它通常和"导入"结构对称。

**一个没有同构对的项目，做完只是"做完了"。**

## 迁移阶梯 T1 → T4

| 档 | 场景 | AI 做什么 | 你做什么 |
|---|---|---|---|
| **T1 照做** | 第一次遇到这个结构 | 给设计 + 骨架 + 步骤 | 填代码，同时理解结构 |
| **T2 复现** | 遇到**同构**的第二个模块 | 不给设计，只说"和上次那个像" | 照上次的样子自己搭 |
| **T3 变式** | 遇到**不同**场景但原理相同 | 只问"这个和上次那个是不是一回事" | 自己判断能不能套，自己设计 |
| **T4 独立** | 新项目 | 只挑刺 | 从零设计和实现 |

**T1 不是要被淘汰的阶段，是必经的起点。** 你现在不负责设计——初学者硬设计只会卡死。你要做的是：先把一个结构走完一遍，然后让它在第二个地方自己长出来。

一个项目里不同模块可以停在不同档：熟的领域直接 T3，不熟的停在 T1。

---

## 设计由 AI 给，但必须带理由

不给理由的设计就是一张看不懂的图纸，你只会照抄。所以设计说明必须包含三件事：

```markdown
## 模块划分
| # | 模块 | 职责 | 边界（不负责什么） |
|---|------|------|------------------|
| 1 | loader | 读 CSV → [{name, amount, date}] | 不做校验 |
| 2 | validate | 校验字段和类型 | 不碰文件 |
| 3 | stats | 算 count / total / avg / max | 不读文件、不渲染 |

## 为什么这么分
- loader 和 validate 拆开：读文件会失败，校验也会失败，两种错要分开报
- stats 不读文件：这样它能被单独跑，不用先造一个 CSV

## 顺序
先做 1、2，因为后面全依赖"干净的数据"

## 同构对
模块 1（读 CSV）↔ 以后要加的"读 JSON"
```

**长度上限：15 行 + 一张模块图。** 超过就是教程，你会跳过。

## 实现密度 L3 → L0

同一个模块，AI 按四种密度交给你，模块内递减：

| 档 | AI 给什么 | 你写什么 |
|---|---|---|
| **L3 手把手** | 签名 + 职责 + 输入输出 + 边界 + **编号实现步骤** + 手算样例 | 照步骤填 |
| **L2 给框架** | 去掉实现步骤 | 自己想步骤 |
| **L1 给签名** | 只给签名 + 一句话职责 | 自己想输入输出和边界 |
| **L0 给问题** | 只给"这个文件解决什么问题"，文件是空的 | 从零设计这个文件 |

起步 L3，每完成 2 个模块降一档。一直停在 L3，你永远在翻译别人的步骤；直接跳 L0，第一步就死。

## 三个反直觉的规则

**① Review 前你必须先自己判断。** 每块结束时，你先写两句：「我觉得最可能出问题的地方是 X」「如果需求变成 Y，我要改这里」。然后 AI 才开口，第一句必须是"你想对了什么"。

AI 先给结论，你练的就只是"接收结论"——那是缩小版的许愿池。

**② 概念要撞三次。** 第一次 AI 讲（≤3 句），第二次在别的模块出现时 AI 不解释、只问"这里和上次那个是不是一回事"，第三次你自己用。只讲一次的叫"听说过"。

**③ 收尾你自己画模块图。** 不是背，是画：几个框、箭头指向哪、数据怎么流。画错 AI 纠正。这是"结构感"唯一的检验方式，两分钟，一张纸。

## 系统零件清单

新手做不出完整系统，往往**不是不会写代码，是从没见过其中某几件**——它们一直被 AI 顺手做了，你连它们的存在都不知道。

| 零件 | 说明 |
|---|---|
| 配置 | 路径、密钥、环境变量 |
| 入口 | 程序从哪开始跑 |
| 数据模型 | 数据长什么样 |
| 业务逻辑 | 真正干活的部分 |
| 错误处理 | 出错时怎么办 |
| 状态 | 东西存在哪，重启后还在不在 |
| 外部依赖 | 库、API、第三方服务 |
| 运行方式 | 怎么启动，怎么确认它活着 |

规则：**每个项目至少接管一个新零件**，哪怕只是"这次启动命令你自己写"。一次都没接管新零件的项目，等于没长进。

## 和其他「教学模式」的区别

| | 谁写代码 | 谁定设计 | 学完会怎样 |
|---|---|---|---|
| 普通的 teach-mode 类技能 | AI | AI | 看懂了，但下次还得问 |
| **本协议** | **你** | AI（必须给理由） | 下次同类的事能自己来 |

判据：**如果一次会话结束时你既没写代码、也没长出"下次能自己来"的东西，那这次就是白做。**

## 使用

第一次开项目，直接说：

> 我想做一个记账工具，用这个方式。

它会问你三件事（做什么、什么技术栈、打算做多久），然后给出**带理由的模块设计**，并明确告诉你：哪两个模块是同构的、第二个什么时候放手给你。

之后每次开工它会读 `.learn/state.md` 恢复进度：你的水平、模块清单、每个模块的迁移档和实现档、系统零件、反复犯的错。

**快捷口令**：`太难了` / `太简单了` / `我卡住了` / `这次我自己来` / `直接做完` / `帮我改`

## 设计依据

`docs/evidence.md` 里有完整证据清单（含 DOI 和链接，分「强 / 中 / 弱 / 个案」四级）。

最硬的五条：

1. **验收只看「撤掉 AI 之后」**。练习期表现与学习结果可以背离——有个近千人的 RCT 里，练习期用 AI 提升 48%~127%，撤掉 AI 后反而比从没用过 AI 的对照组低 17%。
2. **同一个模型，护栏决定方向**。不给答案 + 逐步引导，能把 −17% 扭成不掉（哈佛物理 194 人交叉 RCT，效应 0.63–1.3 SD，还更省时间）。
3. **新手先给完整范例，然后撤**。范例 → 补全 → 独立，跳过「补全」这档会掉效果。T1→T2 和 L3→L0 都依据这条。
4. **先让他卡住，卡完必须讲**。166 项比较的元分析，先解题后讲解 g=0.36；前提是失败之后必须有明确讲解。
5. **别拿「任务完成」当学会**。AI 组没更快却学得更少——效率类指标在这件事上系统性说谎。

## 已知局限

诚实写在前面：

- **没经过真实项目验证。** 这是从证据和一次深度设计访谈里推出来的协议，不是跑过十个项目打磨出来的。
- **「同构模块对」没有直接实验支持。** 「同一结构做两遍能提升迁移」是从脚手架渐撤和样例效应**外推**出来的，方向合理，但不是实证结论。这是整个协议最需要被检验的地方。
- **砍掉了验收。** 只做代码审查，不做「撤掉 AI 重写」这类检验。代价是：你没法客观区分「我写完了」和「我学会了」。迁移阶梯和模块图是替代品，但它们更软。
- **不练「改别人代码」。** 协议只练「从规格写出代码」。维护能力（读懂并改动 AI 写的代码）是另一个技能，目前没覆盖。
- **两个证据空洞。** 「新手+专家配对时谁打字学得更多」和「review AI 代码的学习收益」，都没有对照实验。
- **需要你愿意慢下来。** L3 那档要你手写几十行，第一次你大概率会想「算了让 AI 写完吧」。到那一步，说「太难了」，那是密度该降的信号。
